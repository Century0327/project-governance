# v1.2.0 Change-Budget / Anti-Overfitting 审查

- 日期：2026-09-10

- 依据：docs/audit-v1.1.0-mechanism-audit.md（22 项发现）

- 方法：对每项回答 8 问（已发生 vs 理论 / 真实证据 / 不改的后果 / 修复影响 / 是否有更小修复 / 是否引入新自由度或维护负担 / 能否最小测试证明 / 未来什么证据再改），按原则 A（规范优先）、原则 B（不为自动化而自动化）、原则 C（分批进版）裁定，并做 8 个"修 A 坏 B"反例审查。

- 结论先行：**v1.2.0 只进"真实证据 + 最小方案"的 12 项；10 项降级为暂不修/观察项。全部修改均不改变现有行为判定，新增检查均为告警级。**

## 二、"修 A 坏 B"反例审查（GPT 提出的 8 个风险）

| 反例                            | 审查结论    | 规避方式                                                |
| ----------------------------- | ------- | --------------------------------------------------- |
| 1. index 保护人工内容 → 自动生成不再确定    | **可规避** | 默认**停止+报错**而非静默跳过；机器块仍确定性生成；`--force` 才覆盖人工区        |
| 2. CHANGELOG 固定顶部 → 破坏已有格式兼容  | **可规避** | 只改模板+文档，不动现有 CHANGELOG 文件；规则表述为"最新条目之前"，兼容表格/标题两种格式 |
| 3. placeholder 门禁误判合法占位符      | **可规避** | 门禁仅 warning；定义合法占位符集合（已自动替换的键）；模板示例化后占位符减少          |
| 4. check 增强把旧项目判红             | **可规避** | 新增检查全部 warning 级，不改变 check 通过/失败；诊断增强不改变判定          |
| 5. max\_depth 同源化破坏 CLI 用法    | **可规避** | 元数据优先 + 缺失回退默认 4；显式传参仍优先于元数据                        |
| 6. 默认权限映射覆盖用户判断               | **已规避** | 不做默认映射表，只加"未映射目录保守处理"一句规范                           |
| 7. handoff 限 20 条删有用上下文       | **已规避** | 模板纪律是 AI 指南非强制删除；旧条目归档进 CHANGELOG 有去处               |
| 8. source of truth 变更后旧项目重复状态 | **已规避** | 不删除结构，仅文档化优先序；旧项目行为不变                               |

**结论：8 个反例均可通过最小方案规避，无"必须牺牲兼容性才能修复"的项目。**

## 三、v1.2.0 最终边界

1. **目标**：解决已被真实使用证明的、最值得修的机制问题，保持行为稳定。不是"解决审计发现的所有问题"。
2. **进入项 12 个**（必须修 7 + 建议修 5）：全部不改变现有行为判定；唯一行为变更点是 A-2（index 默认停止+告警，`--force` 覆盖），其目的是**防数据丢失**而非重构。
3. **暂不修 10 个**（A-6/A-8/A-5b/A-7b/A-10b/B-2/B-3/C 类 5 项）：留 DESIGN 观察项，未来出现真实歧义/事故证据后再评估。
4. **配套**：SKILL.md version→1.2.0、CHANGELOG 增 \[1.2.0] 条目（按新位置规则）、README 快速开始/FAQ 微调、DESIGN 增 ADR（index 所有权边界、信息生命周期、批准边界——仅方向性记录）。
5. **确认点不变**：阶段 A 完成后用户确认才提交推送；阶段 B PR 更新前用户确认。
