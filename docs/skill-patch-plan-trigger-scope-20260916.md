## 三、P1/P2 语义审校：通用 Skill 规则 vs 项目具体规则（本轮新增）

|---|---|---|
| "会话开始读 index→handoff→LESSONS" | 具体实现（固定三件套流程） | 上浮了项目流程 → 改为"按任务需要"，用映射表代替 |

| "优先继承 score>0.85 whitelist" | 具体机制细节（阈值） | 上浮了具体数值 → 通用层只写"优先继承已验证条目"，阈值留模板/项目规范 |
| "绝不使用 permanent_ban: true" | 具体机制细节（字段名） | 上浮了字段名 → 通用层写"不使用已标记禁用的条目"，字段名留注册表 schema |
| "新错误记入 LESSONS.md" | 通用治理原则（错误档案） | 保留，并入条件式更新（有可复用价值才记） |
| "会话结束更新三件套" | 具体实现（无条件必更） | 改为条件式（P2） |

**审校结论**：第 3 步有 4 处"项目具体机制"上浮到了通用层（固定三件套、注册表文件、0.85 阈值、permanent_ban 字段名）。v1.2.1 的修法 = SKILL.md 只留通用原则 + 映射表；具体数值与字段名的权威下沉到 templates/AGENTS.md（项目定制区）与注册表 schema。

**一个佐证实例**：用户自己的项目规则写的是"找文件时先找索引，**绝对禁止**直接搜索文件"——比通用 Skill 应有的强度更高。这恰恰说明：*绝对禁止*是作者项目（索引由作者自己维护、始终新鲜）的可行约定，但对陌生用户（索引可能缺失/过期）就是故障源。具体规则不能平移到通用层。

### P1+P2 —— 重写「第 3 步」（原 126-130 行替换为）

```markdown
### 第 3 步 —— 按任务需要执行治理

**核心原则**：本 Skill 不追求"少触发"，而要求触发后只执行与当前任务相关的治理动作。

先判断本次任务需要哪些治理信息，只读取相关文件，不默认读全套：

| 本次任务涉及 | 首选读取 |
|---|---|
| 文件定位 / 项目结构 | `index.md` |
| 上次进度 / 跨会话继续 | `session_handoff.md` |
| 避免重复历史错误 | `LESSONS.md` |
| 版本选择 | `VERSIONS.md` |
| 参数或方案选择 | 项目的参数/方案注册表（如 `whitelist.json` / `blacklist.json`） |
| 架构或项目决策 | `CHANGELOG.md` / `ARCHITECTURE.md` |
| 建立治理体系 | 第 1 步 `init` |
| 治理文件健康检查 | 第 4 步 `validate` / `check` |
| 目录结构变化 | 第 4 步 `index` |

工作中遵循通用治理原则：

- **索引优先**：通过 `index.md` 优先定位文件；索引缺失、过期或无法定位时，搜索文件，并视情况更新索引。
- **参数从注册表取**：项目存在参数/方案注册表时，优先继承已验证条目，不使用已标记禁用的条目。具体字段与阈值以模板和项目规范为准。
- **新错误入档**：发现可复用的错误与纠正，记入 `LESSONS.md`。

任务结束时，只更新发生了变化且有持久价值的治理文件：

- 跨会话仍需继续 → 更新 `session_handoff.md`
- 文件结构发生变化 → 更新 `index.md`
- 形成新的项目/架构决策 → 更新 `CHANGELOG.md`
- 发现可复用的错误与纠正 → 更新 `LESSONS.md`
- 没有对应变化时，不创建或更新治理记录。
```

## 五、验证设计（修订：触发=辅助指标，核心=触发后是否过度介入）

**判定标准**（总原则）：*不要求 Skill 尽可能少触发，而要求它在触发后只执行与当前任务相关的治理动作。*

| 用例 | prompt | 触发预期（辅助） | 核心观测（触发后行为） |
|---|---|---|---|
| A | "帮我修复这个函数的 bug" | 低；若上下文明确在启用治理的项目里，触发不算错 | 是否把普通 bug 修复升级成完整治理流程 |
| B | "上次这个项目做到哪了？" | 高 | 是否只读 handoff/VERSIONS/index 而非全套 |
| C | "哪个版本才是稳定版本？" | 高 | 是否只读 VERSIONS/index 而非全套 |
| D | "我要初始化一个新的 AI 长期项目治理体系" | 高 | 是否走 init 而非日常治理流 |
| E | "帮我写一个 README" | 低 | 是否误启动治理 |
| F | "帮我找一下这个项目当前稳定版本对应的配置文件" | 高（明确治理任务） | **是否只取 index/VERSIONS，不把 handoff/LESSONS/CHANGELOG 全端上来**（本补丁要验的核心） |

**用例梯度**（从"不应治理"到"局部治理"到"完整治理"）：A/E 普通任务不应强行治理 → F 明确治理任务但只需一个局部能力（index/VERSIONS）→ B/C 单项治理（handoff / VERSIONS）→ D 完整治理（init）。

记录表：任务 / 是否触发（辅助）/ 触发后读取了什么 / 是否过度介入（核心）/ 是否完成原任务。
**可行性边界**：会话内部无法观测宿主"触发判定"（description 扫描发生在加载前）；本会话技能列表含大量 skill 是预加载结果，不能作为触发证据。最可靠 = 用户新会话实测（不额外烧积分）；退一步 = 静态判定触发后行为（可执行，因为加载后的指令即 SKILL.md 正文，可直接审查）。

A/B：修改前后用上述用例 + 用户 2-3 个真实任务对照，指标：过度读取 / 漏读关键文件 / 错误更新 / 不需要时启动治理 / 是否完成原任务。
